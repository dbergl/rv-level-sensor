# AC Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The ESP32 leveling sensor also becomes the Firefly panel's RV-C AC (instance 7), bridging to the CountryModPro rooftop unit over Bluetooth, with paired Home Assistant control through the `rv_level` integration.

**Architecture:** Host-testable logic in `lib/` (unit protocol, bridge state machine, RV-C thermostat codec and panel glue, pairing/session crypto, HA message codec), thin NimBLE glue in `src/hal/`, wiring in `src/main.cpp` behind two build options. On the HA side, `rv_level` gains a second config-entry kind ("ac") with its own Bluetooth client and the full `countrymodpro` entity set.

**Tech Stack:** ESP32 Arduino + PlatformIO, NimBLE-Arduino 1.4, Unity host tests (`pio test -e native`), monocypher 4.0.2 (already in `lib/`); Home Assistant custom integration (Python 3.14, bleak / bleak-retry-connector via HA's bluetooth, `cryptography`, `hashlib.blake2b`), pytest-homeassistant-custom-component.

**Spec:** `docs/superpowers/specs/2026-11-01-ac-bridge-design.md` (read its Signal sheet before any task; it is the only source of wire facts).

## Global Constraints

- **Clean room:** do not open `countrypro/`, `velit-hass`, `countrymodpro` or the Pi bridge sources. Every byte value comes from the spec's Signal sheet.
- Unit commands are limited to the spec's allow-list; nothing else may ever be written to the unit.
- At least 400 ms between unit commands; a command with no status frame within 3 s has failed.
- Instance 7. Panel status DGNs sent: 1FFE2, 1FF9C, 1FEFA, 0FFA1 (priority 6), on change and at least every 5 s; never 1FFE1.
- Temperatures on RV-C: uint16 LE, 1/32 °C/bit, offset −273 °C, encoded by rounding **up**.
- Setpoint 61–86 °F, whole degrees; refused while the unit is in °C.
- With the AC bridge on, CPU runs at 240 MHz all the time; AC-off builds keep today's 80 MHz behavior.
- AC-off build behaves exactly as today (all existing tests pass unchanged).
- Both build options off must fail to compile.
- HA entity ids and values match today's `countrymodpro` set (spec entity table), except fresh air and dehumid, which are dropped.
- Code style follows this repo (namespaces per lib, `camelCase` methods, trailing-underscore members, terse comments that say why).

## Review Focus

1. **The unit changes on its own mid-command** (someone uses its remote): the reply shows something else. Expected: the reply is the truth, the intent is reported failed if not satisfied, nothing is retried in a loop. Test in Task 3.
2. **Fragment loss or garbage between frames**: expected resync on the next `5A 5A`, no wedged stream, no false frame. Test in Task 2.
3. **A captured HA command is replayed**, in the same or a later connection: expected rejected. Test in Task 6.
4. **Panel commands while the unit is unreachable**: expected nothing queued; after reconnect nothing old is sent, and the panel stays stale. Test in Tasks 3 and 5.
5. **Setpoint up at 86 °F, down at 61 °F, or heat/dry/unknown panel codes**: expected no command outside 61–86 and no heat/dry command. Test in Task 5.

### Task 3: Bridge state machine (`lib/acbridge`)

**Files:**
- Create: `lib/acbridge/bridge.h`, `lib/acbridge/bridge.cpp`
- Test: `test/test_bridge/test_main.cpp`

**Interfaces:**
- Consumes: `cm::buildCommand`, `cm::FrameAssembler`, `cm::decodeStatus`, `cm::UnitStatus`, `cm::Mode` (Task 2).
- Produces (namespace `ac`):
  - `class IUnitLink { public: virtual bool connected() const = 0; virtual bool write(const uint8_t* d, size_t n) = 0; };`
  - `enum class Op : uint8_t { Power, Mode, Fan, Setpoint, StepSetpoint, Display, Oscillate, Light, Celsius };`
  - `struct Intent { Op op; int8_t value; uint32_t tag; };` — `Mode` values are `cm::Mode` (Cool, Eco, Sleep, Turbo, FanOnly only); `Fan` 0 = auto, 1–5; `Setpoint` °F; `StepSetpoint` ±1; bools as 0/1; `tag` is echoed in the result.
  - `enum class Result : uint8_t { Ok = 0, Refused = 1, Unreachable = 2, NotConfirmed = 3, BadAuth = 4 };` (`BadAuth` is used only by Task 9)
  - `class Bridge { public: explicit Bridge(IUnitLink& link); void submit(const Intent& i, uint32_t nowMs); void onNotify(const uint8_t* d, size_t n, uint32_t nowMs); void tick(uint32_t nowMs); bool responding(uint32_t nowMs) const; const cm::UnitStatus& status() const; uint32_t statusVersion() const; bool takeResult(uint32_t& tag, Result& r); };`
  - Constants: `kGapMs = 400`, `kTimeoutMs = 3000`, `kPollMs = 3000`, `kRespondingMs = 10000`, `kMaxPending = 8`.

Behavior (the decisions the tests pin):
- One intent at a time, FIFO, up to `kMaxPending` (submit beyond that → `Refused`). Each intent expands to an ordered command list from the current status; the intent succeeds when the last command's reply status satisfies it, else `NotConfirmed`.
- Expansion: `Power 0` → `01 01`; `Power 1` → `01 02`. `Mode Cool` → `01 02` if off, then `02 01` unless already Cool/Eco/Sleep/Turbo (then no-op `Ok`). `Mode FanOnly` → power on if off, `02 02`. `Mode Eco/Sleep/Turbo` → `Refused` if off; else `02 04/05/06`. `Fan` → `04 0N` / `04 06`. `Setpoint` / `StepSetpoint` → `Refused` if the unit is in °C or the target leaves 61–86; else `03 <F>`. `Display` → `0A 02/01`; `Oscillate` → `45 01/00`; `Light` → `1C 01/02`; `Celsius` → `20 01/02`.
- `StepSetpoint` counts from the pending setpoint target if a setpoint intent is queued or in flight, else from the reported setpoint.
- Every unit reply replaces `status()` and bumps `statusVersion()` only when the decoded fields change.
- Each command gets one retry after a timeout; then the intent fails `NotConfirmed`.
- While idle, a status query `01 00` every `kPollMs`.
- `submit` while `!link.connected()` or `!responding()` → `Unreachable` immediately; on disconnect, every queued intent fails `Unreachable` and the queue empties.
- `responding(now)` = link connected and a valid frame within `kRespondingMs`.

- `update` sends nothing unless `claimed && bridge.responding(now)`. Then it sends the four status DGNs when `statusVersion()` changed since the last send and at least every `kHeartbeatMs`. Ambient is sent only when `airTempF != 0xFF`.
